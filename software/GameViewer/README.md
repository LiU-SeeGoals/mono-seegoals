# Game Viewer

A React + Vite canvas view of the field, plus a small Node server that
bridges SSL multicast to the browser.

```
server/            Node (CommonJS), not bundled
  visionServer.cjs UDP multicast -> one WebSocket (VITE_SSL_VISION_WS_PORT)
  decode.cjs       protobuf decoding, unit-tested in decode.test.cjs
  dev.cjs          runs Vite and the vision server together
  proto/ssl.json   generated by software/proto-messages/build_ts.sh
src/               React frontend
  hooks/           WebSocket clients (vision server, AI controller)
  state/           live stores the canvas reads at frame rate
  proto/           generated by software/proto-messages/build_ts.sh
```

## Running

```
pnpm install
pnpm run dev       # Vite + vision server; if one exits, both stop
pnpm run server    # vision server only
pnpm test          # server unit tests
pnpm run build     # typecheck + production bundle (what CI runs)
```

## Vision server

Browsers cannot join multicast groups, so `server/visionServer.cjs` does and
forwards over one WebSocket:

| Source | Multicast | Sent to the browser as |
| --- | --- | --- |
| SSL-Vision (raw) | `SSL_VISION_MULTICAST_ADDR` : sim/real main port | binary `SSL_WrapperPacket`; with `?source=tigers` only packets that carry geometry |
| TIGERs tracker | `SSL_TRACKER_ADDR:SSL_TRACKER_PORT` | `{"type":"tracked","update":…}`, only with `?source=tigers` |
| Game controller | `SSL_GAME_CONTROLLER_PUBLISH_ADDR:…_PORT` | `{"type":"referee","referee":{stage,command,yellow,blue}}` |

The sidebar shows the referee command, stage and score, and the Game
Controller status turns green while referee packets arrive.

## Vision source

Choose **Tigers filter** (the default) or **Raw SSL Vision** in the sidebar.
The choice is saved in this browser. Tigers requires a running
auto-referee/tracker publishing to `SSL_TRACKER_ADDR:SSL_TRACKER_PORT`
(default `224.5.23.2:10010`); there is no fallback to raw detections.
In raw mode each camera's latest detections are merged (a robot seen by two
cameras keeps the more confident detection) and a camera that stops sending
drops out after 0.5 s. Robots and balls clear after one second without a
frame or on disconnect.

## AI controller

The controller serves a WebSocket on
`VITE_AI_GAME_VIEWER_SOCKET_ADDR:VITE_AI_GAME_VIEWER_SOCKET_PORT`
(`internal/client/webserver_client.go`). Each packet replaces the actions of
the team(s) it contains; a team that stops sending is dropped after one
second. The sidebar's Game/Manual buttons and clicks on the field send
commands back on the same socket.

## Rendering

Vision and controller data go into the stores in `src/state/stores.ts`, not
React state. The canvas subscribes and redraws at most once per animation
frame; it is resized only when its container's size changes. The robot table
re-renders 5 times a second.
